## 2. 開發環境建置與函式庫安裝

要讓 ESP32 聽懂我們的程式碼，我們需要先將 Arduino IDE 設定好，並安裝專屬的「翻譯字典（函式庫）」。請跟著以下步驟仔細操作：

### 步驟 1：安裝 ESP32 開發板核心

1. **下載編輯器**：前往 Arduino 官網下載並安裝 [Arduino IDE 2.x](https://www.arduino.cc/en/software)。
2. **新增開發板網址**：
   * 開啟 Arduino IDE，點擊左上角選單 `檔案 (File)` > `偏好設定 (Preferences)`。
   * 在對話框下方的「額外的開發板管理員網址」欄位中，完整貼上這段網址：
     `https://raw.githubusercontent.com/espressif/arduino-esp32/gh-pages/package_esp32_index.json`
   * 點擊「確定」。
3. **下載 ESP32 核心**：
   * 點擊 IDE 左側邊欄的 **開發板管理員 (Boards Manager)**（圖示長得像一塊晶片）。
   * 在搜尋框輸入 `esp32`，找到由 **Espressif Systems** 提供的項目。
   * 點擊 **安裝 (Install)**，這會需要幾分鐘的時間下載。

---


### 🚨 新手大坑：找不到序列埠 (Port) 怎麼辦？

核心安裝完後，我們需要把電腦和 ESP32 連接起來。通常我們會在上方工具列的「選擇開發板與連接埠」中，選擇 `ESP32 Dev Module` 以及對應的序列埠（Windows 會顯示 `COM3`、`COM4`；Mac 會顯示 `/dev/cu.usbserial-xxxx`）。

**如果你點開選單，發現「序列埠反白無法選擇」，或是「只看得到藍芽 (Bluetooth)」，請檢查以下兩大魔王：**

1. **你用到了「純充電線」！(佔了 80% 的原因)**
   * 很多買家電或耳機附贈的 Type-C / Micro-USB 線，裡面**只有通電的銅線，沒有傳輸資料的線**。請務必換一條確定可以傳輸資料的線（例如能讓手機連上電腦傳照片的線）。
2. **電腦缺少 USB 晶片驅動程式 (Mac 用戶最常遇到)**
   * ESP32 板子上有一顆負責和電腦溝通的晶片（通常是 `CP2102` 或是 `CH340`）。Windows 10/11 通常會自動抓取，但 **Mac 電腦預設沒有這個驅動程式**！
   * **解法**：觀察你 ESP32 板子上那顆最大的方形晶片寫什麼。
     * 若為 **CP2102**：請上網搜尋 `CP210x USB to UART Bridge VCP Drivers` 下載安裝。
     * 若為 **CH340**：請上網搜尋 `CH340 Mac Driver` 下載安裝。
   * 安裝後，記得要在 Mac 的「系統設定 > 隱私權與安全性」中，允許該驅動程式執行，然後**重新啟動電腦**，序列埠就會神奇地出現了！

## 4. 第一步：錄製並破解冷氣紅外線密碼

一般電視遙控器送出的訊號很短（通常是單一指令，例如「頻道+1」）。但冷氣遙控器送出的是**「狀態包裹 (State Packet)」**，每次按按鍵，它都會把「溫度、風量、風向、模式」全部打包成一長串密碼發射出去。

如果用預設的程式錄音，這段超長密碼很容易「錄到一半就被截斷」，導致你拿去發射時冷氣根本不理你。因此，我們必須修改程式碼中的等待時間（`kTimeout`）。

### 📝 破解專用接收程式碼：

請開一個新的草稿碼，將以下程式碼上傳到 ESP32：

```cpp
#include <Arduino.h>
#include <IRrecv.h>
#include <IRutils.h>

const uint16_t kRecvPin = 15;        // 接收模組的 S 腳位接在 GPIO 15
const uint32_t kBaudRate = 115200;
const uint16_t kCaptureBufferSize = 1024; // 準備超大記憶體來裝冷氣訊號
const uint8_t kTimeout = 150;        // ★ 關鍵破解：將 Timeout 延長到 150ms，確保訊號不被切斷
const uint16_t kMinUnknownSize = 12;

IRrecv irrecv(kRecvPin, kCaptureBufferSize, kTimeout, true);
decode_results results;

void setup() {
  Serial.begin(kBaudRate);
  while (!Serial) delay(50);
  irrecv.setUnknownThreshold(kMinUnknownSize);
  irrecv.enableIRIn();
  Serial.println("\n--- 準備接收超長冷氣訊號 ---");
}

void loop() {
  if (irrecv.decode(&results)) {
    Serial.println("\n--- 收到新訊號！ ---");
    Serial.print("協定類型 (Protocol): ");
    Serial.println(typeToString(results.decode_type));
    Serial.print("長度 (Bits): ");
    Serial.println(results.bits);
    
    // 印出給程式用的陣列
    Serial.println(resultToSourceCode(&results));
    
    irrecv.resume(); // 繼續接收下一筆
  }
}
```
### 🎮 實機操作步驟：怎麼錄？

1. **確認接線與上傳**：確認接收模組接在 GPIO 15，並將上述程式碼上傳。
2. **打開監控視窗**：點擊 Arduino IDE 右上角的「序列埠監控視窗」，確認右下角選在 **`115200 baud`**。
3. **離開冷氣範圍**：帶著你的原廠冷氣遙控器，走到房間外面（或是冷氣絕對感應不到的地方），將遙控器狀態先切換到「關機」。
4. **貼臉輸出**：走回電腦前，把原廠遙控器對準 ESP32 上的「紅外線接收模組」，距離大約 3~5 公分。
5. **按下開機鍵**：按一下遙控器的電源，這時監控視窗就會瞬間印出一大串資料！

---

### 🕵️‍♂️ 數據解讀：怎麼看懂這些密碼？

按下遙控器後，你的監控視窗大概會印出類似這樣的畫面：

```text
--- 收到新訊號！ ---
協定類型 (Protocol): MITSUBISHI_HEAVY_152
長度 (Bits): 152
uint16_t rawData[307] = {3200, 1600, 400, 1200, 400, 400, ... (略)};
```
**我們真正需要得到的，正是 MITSUBISHI_HEAVY_152 這個精確的協定名稱，以及 152 這個長度數字。有了它，我們之後就能直接導入函式庫，呼叫專屬的控制指令。**

**你一定會想問:「我已經知道我的冷氣品牌了，我還需要執行嗎？」
ANS:「要，因為同一個品牌，可能有好幾種不同的遙控協定」**

以我們這次的「三菱」為例，打開函式庫一看，你會發現光是三菱就有超多種：
* `Mitsubishi112` (112 Bits)
* `Mitsubishi136` (136 Bits)
* `MitsubishiHeavy88` (三菱重工 88 Bits)
* `MitsubishiHeavy152` (三菱重工 152 Bits)
如果你只因為知道它是「三菱」，就隨便盲猜一個 `Mitsubishi112` 去寫程式，結果冷氣根本不會動，你就會陷入「是我接線接錯？還是模組燒壞？」的無盡自我懷疑中。

**💡 結論：錄製的真正目的**
**我們進行「第一步：錄製訊號」，與其說是為了找品牌，不如說是為了「確認協定與密碼長度 (Bits)」**
當監控視窗明確印出 `長度: 152` 時，我們就能在茫茫的函式庫中，精準挑出 `IRMitsubishiHeavy152Ac` 這個對的翻譯官，省下你盲猜與除錯的幾個小時！

當然，如果你要幫家裡第二台「同型號」的冷氣做遙控器，因為你已經確切知道它是 152 Bits 版本了，這時候你就可以直接跳過錄製步驟，直接把最終版程式碼燒進去囉！

## 5. 實戰避坑指南：常見硬體與通訊陷阱

如果你已經順利錄到 `MITSUBISHI_HEAVY_152`，恭喜！不過在組裝最終版之前，還有幾個很容易讓人卡住的地方，先提醒你：

1. **接收成功，不代表發射也接對了。** 接收模組的訊號腳接 GPIO 15；發射模組的訊號腳則接 GPIO 4。燒錄最終版後，真正要面向冷氣的是「發射模組」。
2. **先確認模組的腳位與電壓。** 不同商品的 `S`、`+`、`-` 排列可能不同，請以模組上的標示和規格為準。ESP32 的 GPIO 不能直接承受 5V 訊號；如果你用的是單顆紅外線 LED，而非帶驅動的三腳模組，也不能直接照三腳模組的接法使用。
3. **協定一定要對。** 下面的程式使用 `IRMitsubishiHeavy152Ac`。如果你在第 4 步錄到的是其他協定或 `UNKNOWN`，請先不要直接燒錄最終版。
4. **Wi-Fi 連上了，網址卻打不開？** 最終版程式把 ESP32 的 IP 設成 `192.168.1.200`，閘道設成 `192.168.1.1`。這組數字只有在你的路由器網段相符、且該 IP 沒被其他裝置使用時才適合。若你家不是 `192.168.1.x` 網段，就要依路由器資訊調整。
5. **紅外線要有適合的角度與距離。** 網頁上的按鈕能按，不代表冷氣已經收到紅外線。先把發射器靠近冷氣接收窗、對準測試，成功後再找固定擺放位置。

## 6. 第二步：全功能 Web 遙控器程式碼

以下是你提供的 `esp32_ac_remote.main.ino` 程式，**只把 Wi-Fi 名稱與密碼改成佔位文字**，方便放進 HackMD。請在自己電腦上的程式副本填入 Wi-Fi 資料，再燒錄到 ESP32；公開文章不要貼出真實密碼。

這段程式可透過手機網頁控制開關、18～30°C 溫度、冷氣／除濕／送風模式、風量、風向，以及自訂定時關機。若你的冷氣功能或紅外線協定不同，仍要以實機測試結果為準。

> ⚠️ **先知道目前程式的行為：** ESP32 每次重新開機，`setup()` 都會執行 `ac.on(); updateAC();`，因此會發送一次開機訊號。部署前請確認這符合你的需求。這裡忠實保留你的程式，沒有擅自改動這段邏輯。


### 看懂幾個關鍵區塊

* `IRMitsubishiHeavy152Ac ac(kIrLed);`：建立三菱重工 152-bit 紅外線控制物件，使用 GPIO 4 發射。
* `updateAC()`：把模式、風量、風向與溫度寫入控制物件，再一次送出狀態。
* `htmlPage`：直接存在 ESP32 程式中的網頁。手機打開 ESP32 的 IP，看到的就是這段 HTML。
* `server.on(...)`：把不同網址對應到按鈕功能，例如 `/tempUp` 是升溫，`/off` 是關機。
* `millis()`：定時器使用 ESP32 的運作時間計算到期時間；ESP32 一旦斷電或重新啟動，計時就會重設。

## 7. 第三步：燒錄、連線與手機端操作

### 步驟 1：填入 Wi-Fi 資料並燒錄

1. 把第 6 節的完整程式複製到 Arduino IDE。
2. 將 `YOUR_WIFI_NAME`、`YOUR_WIFI_PASSWORD` 改成你家 Wi-Fi 的名稱與密碼。
3. 先確認程式中的 `local_IP`、`gateway`、`subnet` 符合你家的網路。若你不確定，就先查看路由器的 LAN 設定，不要直接假設 `192.168.1.200` 一定能用。
4. 選擇對應的 ESP32 開發板與序列埠，按「驗證」再按「上傳」。
5. 上傳後開啟序列埠監控視窗，速率設定為 **115200 baud**。

### 步驟 2：用手機打開控制網頁

成功連上 Wi-Fi 後，序列埠監控視窗會顯示類似：

```text
✅ Wi-Fi 連線成功
網址: http://192.168.1.200
```

讓手機連上同一個 Wi-Fi，並在瀏覽器輸入監控視窗顯示的網址。請以**實際印出的 IP** 為準。如果序列埠一直只印出 `.`，表示還沒連上 Wi-Fi，先檢查名稱、密碼與訊號。

### 步驟 3：逐項測試

先按「開冷氣」，確認冷氣有反應；再試升降溫、模式、風量、風向與關機。每按一次模式、風量或風向，網頁會切到下一個選項。溫度則限制在 **18～30°C**。

要設定定時關機，在網頁輸入小時數後按「啟動」。到時間後，ESP32 會發送關機紅外線訊號。**如果你重新開機、斷電，或按了開／關機，原本的定時就會失效。**

### 如果按了按鈕，冷氣還是沒反應？

照這個順序檢查：

1. 手機能否開啟網頁？若不能，先處理 Wi-Fi、IP 與手機是否在同一個區域網路。
2. 網頁能開，冷氣卻不動？確認第 4 節錄到的協定、GPIO 4 接線與發射模組供電。
3. 接線沒問題？把發射器移近冷氣接收窗，重新對準測試。
4. 原廠遙控器能控制，但 ESP32 仍不行？重新錄製訊號，確認你的機型確實是 `MITSUBISHI_HEAVY_152`。

最後提醒：這個網頁顯示的是 **ESP32 自己記錄的設定**，沒有從冷氣讀回實際狀態。如果你同時使用原廠遙控器，網頁顯示和冷氣實際狀態可能不同步。網頁也只供同一個區域網路使用，並沒有設定外網遠端控制。
